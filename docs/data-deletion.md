# HexiSweep: запрос удаления данных

## Вариант только на GitHub Pages

Владелец уточнил: сервера нет, использовать только GitHub. Поэтому реализация
содержит публичную инструкцию и прямое обращение по email, **не веб-форму**.
Backend, Turnstile, сторонний сервис форм и имитация отправки не используются.
GitHub Pages не выполняет серверную проверку капчи или доставку почты.

Планируемый адрес после согласованной публикации:
`https://art1shock.github.io/hexitools-site/hexisweep/delete-data/`.
Наличие файлов в ветке само по себе не подтверждает публикацию этого URL.

Кнопка открывает почтовое приложение с локализованным черновиком. Письмо
отправляет сам пользователь. Всегда виден адрес `arturich.pog@gmail.com`:
его можно скопировать и написать через любую почту. Без JavaScript доступны
инструкции на всех шести языках и ссылки email. Содержимое обращения не
собирается сайтом, не помещается в URL сайта, не записывается в браузерное
хранилище и не отправляется обработчику. Параметры `mailto:` - только заранее
заданный шаблон, без введённых посетителем персональных данных.

## Как получать и обрабатывать обращения

1. Получать письма на `arturich.pog@gmail.com`. Для удобства можно вручную
   завести ярлык HexiSweep / удаление данных по теме письма. Код не настраивает
   почтовый ящик и ничего не отправляет от имени разработчика.
2. До проверки не сообщать отправителю, найдена ли переписка по названному адресу.
   Связаться с адресом предыдущего обращения и получить подтверждение запроса.
   Не считать указанный в тексте email доказательством владения адресом.
3. Уточнять только необходимый состав удаления. Не запрашивать пароли,
   документы, IMEI, фотографии или ненужные вложения.
4. После проверки удалить доступные разработчику сообщения, отчёты, вложения
   и отдельные сохранённые копии в согласованном составе. Учесть корзину почты
   и копии вне почтового ящика. Не заявлять, что удалены локальные данные телефона
   или диагностика из систем Google, если разработчик не может это выполнить.
5. Ответить, что реально выполнено. При конкретном обязательном сохранении
   указывать подтверждённые данные, основание, цель и срок; не выдумывать их.

## Хранение

Используется существующее правило политики: письма и добровольно присланные
отчёты удаляются не позднее 90 дней **после решения вопроса**, кроме обязательного
хранения по закону. Это не срок от момента сбора и не отсрочка каждого запроса
на удаление на 90 дней. Само правило не обязывает хранить письмо все 90 дней.

Владелец сообщил, что не знает конкретных дополнительных обязательств хранения.
Новые основания и сроки не добавлены. Конкретные обязательные исключения остаются
неподтверждёнными; страница не утверждает, что таких исключений никогда не бывает.
Перед публикацией владелец должен согласовать этот текст и упрощение до email.

## Настройка и публикация

- Новые аккаунты, ключи, платные ресурсы и обработчики данных не подключаются.
- Статический хостинг и существующий почтовый ящик остаются прежними.
- Веб-форма с серверным антиспамом из первоначального промпта в этом варианте
  **не реализована**. Защита самого почтового ящика от спама остаётся у почтового
  провайдера; абсолютная защита не обещается.
- Сохраняются шесть языков, переключатель, выбор языка браузера и предпочтение
  пользователя по тем же ключам, что у политики. Сохраняется возможность читать
  страницу без JavaScript. Ссылки на политику открываются в новой вкладке.
- Публиковать после согласования email-варианта: слить проверенную ветку в `main`,
  дождаться GitHub Pages и проверить HTTPS URL, шесть языков и `mailto:` на устройстве
  с настроенной почтой. В автоматической проверке настоящее письмо не отправляется.
- Android-приложение и Google Play Console не изменялись. Нельзя гарантировать
  одобрение Google; пока страница не опубликована, не выдавать URL за готовый.

## Выполненные проверки (19 октября 2026)

- 392 проверки в Chromium и WebKit: шесть языков, ширина 320/390/1440 px,
  отсутствие горизонтальной прокрутки, переключатель и автоопределение языка,
  ссылки из политики, фиксированный получатель и локализованный шаблон письма.
- Режим без JavaScript: все шесть инструкций и прямые email-ссылки доступны.
- Десктопный и мобильный скриншоты просмотрены; синтаксис JavaScript и Git diff
  проверены. Новые файлы не используют внешние скрипты или серверные секреты.
- Фактическая доставка письма и запуск почтового клиента не проверялись:
  почта открывается средствами устройства, а отправку выполняет пользователь.
- Тесты серверной формы, капчи, rate limit и истёкшего токена неприменимы:
  в согласуемом варианте только на GitHub этих компонентов нет. Это ограничение,
  а не заявление об успешной серверной защите от спама.
